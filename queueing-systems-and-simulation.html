Queueing Systems and Simulation

C. Rodríguez Morales November 6, 2026

I am taking this course in the fall of 2026, and it is teaching me how to study systems where randomness is part of the story: customers arriving at unpredictable times, machines that break down, and processes that never take exactly the same amount of time twice. Instead of experimenting on a real factory or service line, I am learning to build computer simulation models of these systems, test changes safely, and use statistics to decide which design truly performs best.

  • The technical skills gained: 
    • Simulation Fundamentals - Understanding when and why to simulate, the steps of a simulation study, and how discrete-event simulation models a system as a sequence of events over time.
    • Input Modeling - Selecting and fitting probability distributions to real data so that arrivals, processing times, and failures in the model behave like the real system.
    • Random Numbers and Random Variates - Generating and testing random numbers, transforming them into values from specific distributions, and building Monte Carlo and spreadsheet simulations.
    • Discrete-Event Modeling in Simio - Building and animating models with resources, workers, vehicles, machine reliability, data tables, relational tables, entity routing, and custom processes.
    • Model Verification and Validation - Checking that a model is built correctly and that it accurately represents the real system before trusting its results.
    • Output Analysis - Analyzing terminating and steady-state simulations, building confidence intervals for performance measures, and comparing alternative system configurations to select the best one.
    • Variance Reduction Techniques - Using common random numbers and antithetic variates to get more precise comparisons from fewer simulation runs.

The Tools

Simio: Simio is the simulation software at the center of this course. It lets you build a model of a real system by placing objects such as sources, servers, conveyors, and sinks on a 3D facility view, connecting them with paths, and then watching the system run in real time. Through a series of hands-on labs, I learned to go beyond the drag-and-drop basics: storing product data in tables, routing parts by type, modeling workers, vehicles, and machine failures, and writing custom process logic for behavior the standard objects can't handle on their own. Simio also runs multiple replications of a model and reports performance measures with confidence intervals, which is what turns an animation into evidence for a decision.

Minitab: A simulation is only as good as the data that goes into it and the statistics applied to what comes out of it, and that is where Minitab comes in. I used Minitab on the input side to explore data with scatter plots, test for normality, and run goodness-of-fit tests to choose the right probability distribution for arrival and processing times. On the output side, I used it to compare system designs with statistical tests such as the two-sample t-test, the paired t-test, and ANOVA, so that a recommendation rests on real differences in performance and not on random noise.

Course Case Study: SM Electronics

 Team project — ININ 5025: Queueing Systems and Simulation (in progress)

The problem: SM Electronics, a small manufacturer of electronic parts, has three automated lines that each produce one part type (A, B, and C) and feed a fourth, shared line where the final operations are done. As the product mix shifted over time, that fourth line became a bottleneck. Parts merge onto an input conveyor that holds only 40 units, and when it fills up, incoming parts are lost, at a cost of $0.63 to $0.89 each. Inside the line, parts ride on 40 pallets through eight work cells on a loop conveyor; five cells are automated and need a setup every time the part type changes, and two are manual with variable processing times. The company is considering two costly fixes: adding pallets to the line ($17,000 plus $3,000 per pallet) or installing three new buffer conveyors that release parts in same-type batches to reduce setups ($56,000). Our team was asked to determine the weekly cost of lost production today and whether either modification, both, or neither makes economic sense.

Our approach: Because arrivals, jams, and manual processing times are all random, the interactions in this system are too complex for hand calculations alone, which makes it a good fit for simulation. We built a current-state model of the line in Simio: three part arrival streams with random jam delays, a merge onto the 40-part input conveyor that records lost parts by type, a combined load/unload station for the pallets, and seven work cells on accumulating conveyors. We stored all setup and operation times in a data table and used state variables so that each automated cell remembers the last part type it processed and only performs a setup when the type changes. Before modeling, we also ran quick hand calculations as a sanity check, which showed that with setups every automated cell takes longer per part than the time between arrivals, so a large share of parts is likely being lost today. We presented the current-state model at the project's progress presentation.

Next steps: Since the line restarts each day with unfinished parts still in place, we will treat it as a steady-state system with a warm-up period. We will then estimate the weekly cost of lost production, model both proposed modifications (including the batch release logic for the buffer conveyors), and compare all alternatives statistically to recommend the most cost-effective configuration.

Skills applied: Discrete-event simulation, Simio modeling (data tables, state variables, conveyors, combiners and separators), input modeling, steady-state output analysis, comparison of alternatives, cost analysis, teamwork and technical presentation
